How this simulation actually coordinates itself

What's really running

  • Same algorithm as the full prototype, ported to JS — not a simplified stand-in.
  • Idle robots bid on each open task (distance + battery penalty); lowest bid wins — no dispatcher decides.
  • Every tick, each robot only publishes its own intended next cell; conflicts resolve by "longest wait wins."
  • Urgent tasks (a STAT order, a stalled cell) get first pick of the idle fleet each tick — the auction rule doesn't change, just whose turn it is to draw bidders.

Watch for this

  • Two robots meeting at a teal-ringed chokepoint node — one yields, resolved without a referee.
  • An idle robot parked on a busy cell steps aside after 3 ticks (the courtesy-yield fix — this was a real livelock we hit in testing).
  • An orange glow pooling around a node is the congestion heatmap — nodes where robots keep getting stuck, decaying back down once traffic clears.
  • Kill task server: no new work is announced, but open tasks still get finished. Kill a moving robot: its task is re-announced and won by someone else within a tick.

Honest simplification

  • All robots run in one browser tab here, same as the one-process build. The message-bus discipline (no robot reads another's state directly) is real; literal separate sockets is a one-file swap in the full prototype, not shown in this artifact.
Where this deploys in the real world

E-commerce fulfillment

  • Amazon/Ocado-style centers: totes shuttle pick face → pack station continuously.
  • A wide, evenly-loaded fleet (this scenario runs 14 AMRs) is what keeps pack queues short at peak.

Hospital logistics

  • TUG-style robots already ferry meds, linens and lab samples between wards at hospitals like UCSF.
  • A STAT order needs to cut the queue safely — this scenario runs urgency at 40% of tasks.

Ports & container yards

  • Rotterdam and Qingdao run AGV fleets moving containers between stacks and quay cranes 24/7.
  • Zero tolerance for one dispatcher going down — exactly the kill-switch demo above.

Manufacturing lines

  • Just-in-time assembly (automotive, electronics) feeds kitted parts to cells on demand.
  • A fleet reroutes itself around a jam instead of a fixed conveyor stalling the whole line.

Disaster response

  • No reliable central network in a disaster zone — peer-to-peer coordination isn't optional.
  • Most tasks are urgent by definition; this scenario sets urgency to 55%.

Also applicable

  • Agriculture — fleets of harvesting/spraying robots coordinating field zones without cell coverage.
  • Mining — underground haul trucks and loaders, same collision-avoidance rule, no radio line-of-sight to a control room.
